# Sprint 2 — durable tender workspace contract

Status: implementation contract, 27 September 2026. The Sprint 2 implementation is opt-in and locally verified; see [verification and activation boundaries](TENDER_WORKSPACE_SPRINT2_VERIFICATION.md). This does not authorize a production migration. Scope is the signed-in `/hub` → `/desk` workflow; `/demo`, the synthetic Trace fixtures, and published `frozen-decision-record-v1` case hashes stay unchanged.

## Boundary and records

Use `requireTraceViewer()` for the existing verified WorkOS identity and active organization membership, `withTenant()` for every database operation, the restricted `traceli_app` role with forced tenant RLS, composite `(organization_id, procurement_id, …)` foreign keys, and `appendAuditEvent()` inside the write transaction. Do not create another login, tenant selector, or organization id input. The loopback fixture mode is for disposable local testing only. An organization role is necessary but insufficient: each read, mutation, and export must also resolve the requested tender and its access rule inside that tenant transaction. An unknown, cross-tenant, or unassigned tender returns the same unavailable response.

Use `procurements` as the tenant-scoped tender root and add `tender_workspaces` (one row per `(organization_id, procurement_id)`). A new tender creates both rows atomically. `procurements.reference` is a server-generated stable `TENDER-<uuid>`; the user's name is `title`, not a unique reference. Existing required `region` is `Unknown` until supplied, `status` is `draft`, `evidence_coverage` is 0, and `blocker_summary` is empty. `tender_workspaces` holds `owner_id`, `primary_pack_id`, `pack_version`, `current_revision` (integer, starts 0), `current_draft_id`, `current_assessment_id`, `current_judgment_id`, `updated_at`; only this cursor row is mutable. Validate the pack id against the seeded catalog and resolve its version on the server. Do not reinterpret an older snapshot when the catalog changes.

Add `tender_access` keyed by `(organization_id, procurement_id, user_id)` with `access` = `read` or `review`, granted by/at, and composite tender FK. The creator gets `review` in the create transaction. Director and workspace admin have tenant-wide tender access; other roles require an explicit row. Before issuing a grant, verify the target has exactly one active membership in the same WorkOS organization and an allowed Trace role; deny ambiguous/inactive memberships. Grant/revoke is an elevated action, audited and transactionally checked. This is an authorization list, not a second identity system: every later request rechecks the actor's current WorkOS role/membership and live tender grant, so a historic grant cannot revive an inactive membership.

Add `tender_manual_versions` with server UUID, tender scope, immutable ordinal/version label, label, original filename, media type, byte size, `sha256`, `hash_kind` (`server_verified_upload` or `client_declared_unverified`), `source_version_id` nullable, recorded actor/time, and `supersedes_id` nullable. A manual intake hashes transient uploaded bytes server-side (same 8 MB/type guard as Desk), writes metadata only, and drops bytes. When creating a later version, append a row; never overwrite a referenced manual. A locally imported filename/hash is a declaration until the user reselects the file and the server verifies it. Existing `source_documents`/`source_versions` may be linked when their same-tender provenance and custody are established; do not manufacture a `source_versions.content_hash_kind` that conflicts with its current `metadata_unverified` constraint. Drafts reference specific immutable versions, never live manual labels.

Add append-only `tender_packet_receipts` for each `/desk/checklist` run: tenant/tender, pack id/version **and full canonical pack definition/hash**, server-computed source SHA-256, filename/media type/size, provider id, bounded sanitized extraction/checklist payload, payload hash, actor/time, and explicit `synthetic` or `customer` classification. Issue against that pinned pack definition, never the mutable current catalog. File and vendor response bytes are discarded. An extraction payload can retain only the field values, short source excerpts, page anchors, and provenance required by the checklist; cap row and total JSON size, exclude raw document text and credentials. This receipt establishes what the server actually returned; a browser copy alone cannot establish issuance. It is still *extracted or asserted evidence*, not proof that the underlying document is true. Synthetic fixtures remain labelled synthetic. Customer excerpts may be persisted only after a customer classification and retention policy is configured; absent that gate, refuse customer packet persistence/issuance rather than silently use the synthetic label. If a later source viewer is required, file custody and access policy are a separate explicit dependency.

Add append-only `tender_draft_revisions`: UUID, tenant/tender, monotonically increasing revision, parent draft id, packet receipt id, reviewed checklist, reviewer decision rows, actor/time, canonical payload hash. A scoped `tender_draft_manuals` join table pins each draft to immutable manual version ids with composite FKs. `tender_workspaces.current_revision` is the concurrency cursor. The draft API accepts only reviewer-editable decision, value, page, quote and note fields keyed to receipt row ids; reject supplied provenance, actor, organization, source identity, pack/version or hash. Rebuild original extraction/provenance from the server receipt and stamp `reviewedBy`/`reviewedAt` from the authenticated actor/server time. Validate every row/source reference against that tender's receipt, preserve `missing` versus `negative`, and recompute the canonical hash server-side. Each save requires `expectedRevision` and `idempotencyKey`; under a tender lock, compare-and-swap the cursor, insert revision and audit event, and return the new revision/ETag. Add append-only `tender_commands` with tenant/tender, actor, action, idempotency key, canonical input hash, response id, and a unique `(organization_id, action, idempotency_key)`. Same actor + action + identical canonical input replay returns the original response; a reused key with changed input or actor is a conflict. A stale revision is HTTP 409 with the latest revision metadata, never last-write-wins.

Add immutable `tender_issued_records`: UUID, tenant/tender, `kind` (`assessment`, `human_judgment`, or `exception_proposal`), draft revision id, parent assessment/record id, schema-tagged payload, snapshot/packs hashes, canonical payload hash, issuing actor/time. Add a unique `(organization_id, procurement_id, record_id)` and scoped FKs to the exact draft and parent. Database triggers reject UPDATE/DELETE, as for Trace. Freeze accepts only tender id, `expectedRevision`, and idempotency key: load the current persisted draft and receipt, recompute rules and `freezeAtJudgment` on the server with server actor/time/record id, run `verifyFrozenRecord`, insert issued record + audit + command receipt in one transaction. A human judgment also takes a validated action/reason and expected assessment id/hash; it loads that exact server-issued assessment and verifies lineage. Request-evidence/escalate can issue the existing `frozen-decision-record-v1`; an exception proposal uses a separate immutable schema tagged `exception-proposal-v1` with assessment id/hash, actor, time and reason. It does **not** issue a v1 `accept_with_exception` freeze, because that schema requires a waiver reference and the current desk stub is not an authority. Do not accept browser-supplied frozen records, snapshot hashes, actor ids, waiver authority, or PDF payloads as authority. Retain the existing v1 hash algorithm and schema without rewriting published cases; changes to record meaning require a new version and explicit migration, not an in-place reinterpretation.

`Accept with exception` is a recorded proposed disposition, **not** formal exception approval. The current Desk waiver stub must not be presented as delegated authority. Until an approval policy, approver identity/separation, and supporting evidence are implemented and tested, PDF and UI say “exception proposed; approval not recorded,” and no action marks an exception approved or the award authorized.

## Actions and interface

| Action | Officer | Panel member | Director / admin | Auditor |
| --- | --- | --- | --- | --- |
| List/read tender, record, PDF | Own or explicit access | Explicit access | Any org tender | Explicit access |
| Create tender; edit/checklist/save draft | Create; assigned `review` | Assigned `review` | Yes | No |
| Issue assessment; request evidence/escalate judgment | Assigned `review` | No | Yes | No |
| Record proposed accept-with-exception judgment | No | No | Yes | No |
| Grant/revoke tender access | No | No | Yes | No |

`GET /api/tenders` returns a paged, updated-descending list of authorized tender summaries; `POST /api/tenders` creates a named tender. `GET /api/tenders/{id}` returns tender, exact current draft and issued-record summaries plus `revision`/ETag; a separately requested record returns its immutable payload after authorization and integrity verification. `POST /api/tenders/{id}/manuals` records a verified manual version. `POST /api/tenders/{id}/packets` performs transient extraction and creates a receipt. `PUT /api/tenders/{id}/draft` saves a validated revision. `POST /api/tenders/{id}/assessments` and `/judgments` issue records. `GET /api/tenders/{id}/records/{recordId}/pilot-report` takes only path ids: reload and verify the server record, its draft/receipt/manual versions and judgment lineage, render the PDF, and record an append-only `tender_export_receipts` row (actor, record id, PDF hash, time) plus audit event in the same authorized flow. Use strict input schemas, body limits, same-origin checks for cookie-authenticated writes, `Cache-Control: private, no-store`, and consistent 400/403-or-404/409/500 responses. Do not expose tenant-wide IDs or row existence through error details. List queries fetch summaries only; opening one tender loads its bounded current revision. Reuse a saved packet receipt when the reviewer edits fields, and run extraction only for a newly selected file. Debounce edits and avoid polling or repeated judgment runs; pack evaluation happens at issuance against the saved revision.

Hub lists saved tenders after sign-in and offers Resume. Desk uses the tender URL/id as its durable context; initial load has explicit loading, empty, unavailable, and error states. Draft edits show `Saving…`, `Saved` with revision/time, or `Could not save — retry`; a failed save keeps edits in memory and blocks freeze until committed. A 409 shows that another version exists and offers reload/compare, without silently replacing either version. Reopening on another device loads the server draft and issued records. `sessionStorage` can hold unsaved form edits only and is cleared after confirmed save; `localStorage` Hub entries are optional untrusted import candidates, never automatically merged into authoritative tenders or silently reissued as frozen records. Import asks the user to review names, pack and manual provenance; all imported records start as drafts, and manual hashes remain unverified until reselected. Existing public/demo records remain where they are.

## Delivery order and gates

1. Add one additive migration and Drizzle schema for the scoped tables, FKs, checks, indexes, RLS, restricted grants, append-only triggers, and command/receipt uniqueness. Preflight conflicts before migration; keep rollback additive (disable new path, retain rows). No production data rewrite.
2. Build a small tender store using the existing Trace transaction, lock, audit, and idempotency patterns. Implement role plus tender action checks and strict validators before routes. Start with create/list/read/manual receipts/draft save; then assessment/judgment issuance; then PDF from persisted records.
3. Switch Hub/Desk to server list/resume/save/issue/export and explicit state. Keep the browser draft import clearly provisional. Only remove old browser-only authoritative presentation after the new path passes gates.
4. Test on a disposable local Postgres with all migrations and `traceli_app` active. Exercise two organizations, two tenders in one organization, every role, absent/removed grant, forged organization/tender/actor/record ids, cross-tender manual/receipt links, old draft revision, duplicate and altered idempotency replay, concurrent saves/freezes, mutated record payload/hash, missing-versus-negative round trip, and a forced failure after each insert to prove cursor/record/audit/command rollback together. Verify PDF uses the retained issued record after a browser payload is changed, rejects an assessment/judgment mismatch, and emits no file bytes or secrets. Run existing v1 hash fixtures unchanged, relevant Desk/Hub tests, typecheck and build. No shared, staging, or production database command is part of this plan.

Owner decisions before customer activation: configure classification and retention periods for sanitized customer excerpts/records and export receipts, and decide who may grant panel/auditor tender access. Defaults: synthetic fixtures only until the customer-data gate is configured, director/admin grants only, and no formal exception approval. Source viewing requires an explicit file-custody design and authorization review later.

## Implementation clarifications

The new path is off unless `TRACELI_TENDER_WORKSPACES=1`. It never falls back to browser saving after a server failure. Packet and manual ingestion currently requires the local fixture identity and mock extraction; customer ingestion is closed in code. Customer classification/retention activation requires follow-on policy implementation and verification, not simply a flag or a document.

An idempotent draft retry returns the saved result while its draft is still current. If another writer has advanced the cursor, the retry returns a 409 and the latest revision rather than mislabelling the caller's stale edits as saved. Issuance receipts remain replayable by exact command.

The reviewed browser import creates a new server tender from the confirmed name and pack. It displays the old manual labels/hashes as unverified; files must be reselected to add verified manual versions. It never promotes browser freezes or imports their authority. Panel/auditor access has grant/revoke endpoints; a membership-management screen remains later UI work.
