## Usable slice

`/workspace/trace` offers fictional U/M/G cases and additional failed-check/exclusion/unknown-date/timeout/invalid-response scenarios. One requirement, supplied-evidence snapshot and decision occasion per unit. Lead with result, short reason and next action, then evidence disclosure, then technical provenance. A fixed fixture revision supplies a missing signed note or corrects a source into a linked new unit; earlier records remain visible. No arbitrary upload or URL fetch, corpus ingestion, benchmark count or automatic procurement authorization.

Reuse Next.js, server-only domain code, PostgreSQL, transaction-local tenant role/RLS, existing procurement scaffold and appendAuditEvent. The ordinary authenticated entry resolves current active WorkOS membership on every operation, derives tenant/actor/role on the server and fails closed on lookup failure. A separate local fixture identity is available only with an explicit server flag, nonproduction, no Vercel runtime and a strictly loopback PostgreSQL URL; no browser-supplied identity. It must be impossible to enable local identity against a remote database. The local route is bound to loopback for verification. Roles: all existing workspace roles may read; officer/director/admin may create revisions and record dispositions; only director/admin may override; all readers may create a redacted export for themselves. Full export is limited to director/admin. No arbitrary recipient or sharing.

## Persistence and integrity

Add migration 0010, applied only to an isolated disposable local PostgreSQL instance for this task. New tables reuse organization/procurement scope: immutable Trace units (one frozen, schema-validated JSON artifact), append-only human dispositions, export grants, grant revocations, and immutable export receipts. A unit contains materialized common envelope, retained UTF-8 fictional source versions, immutable source manifest/obligation/profile/constraint/pack, supplied/missing evidence snapshot, decision unit, mock evaluation and deterministic policy assessment. All nested scoped references resolve to exact versions inside the same procurement; validation rejects foreign references. Unit SQL scope and payload scope must agree. Content and snapshot hashes use sorted-key canonical JSON v1, source hashes identify exact retained UTF-8 bytes. Validate all hashes and references on every read, including source fetch and export. Each material record carries synthetic classification, version/actor/job/state/supersedes provenance; no compact M02 example is directly ingested.

Composite foreign keys enforce same-tenant and same-procurement previous-unit, disposition, grant, revocation and receipt links. Unique tenant/action/idempotency keys bind input hashes; replay with changed content fails. Lock the procurement/unit in a transaction for review/revision/export races; expected artifact hash plus expected human-decision sequence is mandatory. Revision marks a previous unit stale for new review/export; history remains inspectable. SQL denies update/delete of frozen units, dispositions and export receipts. New grants cannot silently widen existing grants; revocation appends an event. Minimal audit records are committed atomically with mutations.

Harden legacy product links as part of 0010: nullable source effective_at with honest provenance status for existing unverified dates; no fabricated backfill. Locked source versions become immutable. Enforce source-document procurement stability, requirement/source procurement compatibility, and finding/requirement procurement compatibility using composite keys or guarded SQL triggers, including updates to referenced parents. Migration preflight aborts on inconsistent existing links instead of silently rewriting history. Keep legacy metadata hashes labeled as metadata; no conversion into byte hashes.

## Complete bounded fixture schema

Strict schemas reject unknown keys, invalid ISO date facts, malformed IDs/hashes, non-finite probabilities and excessive content. Limits: at most 8 sources, 16 assertions, 8 constraints, source 16 KiB, unit 128 KiB, rationale 20–2000 characters, exact controlled scenario/action/mode identifiers. Date facts are nullable with precision, basis reference and unknown reason; retrieval never substitutes for effective date. One allowlisted deterministic check implementation verifies a fictional signed review note before the fictional decision date. Positive absence in the supplied packet is unknown, affirmative late/unsigned evidence is not_satisfied, explicit exclusion is not_applicable, unknown effective date is unknown applicability, and competing instruments produce conflict. No stored string executes code.

Source versions, obligation, profile and pack have explicit fixture review status and are ineligible for real decisions. Frozen input and policy version/digest are bound to the assessment. Model assessment is a separately labeled offline fixture (or timeout/invalid), no live fallback. Distributions must be complete and valid. Policy failure stays visible alongside high model confidence; execution failure is cannot_evaluate when model assistance is requested, while deterministic checks remain separately visible. All-satisfied stops at ready_for_review.

## Human decision and export

Actions: accept_assessment, request_evidence, request_rule_review, override_assessment, decline_decision. Require rationale, exact unit/policy/input hashes and optimistic decision sequence. Override requires director/admin, cited fixture evidence and an allowlisted fixture exception-authority reference plus original outcome; it preserves original assessment. Acceptance acknowledges only the scoped assessment. Reviewer identity and role are server-derived. A stale write returns a visible conflict, retains the local draft and offers reload of the latest record.

Export is a server-generated JSON attachment with a manifest that reconstructs the disclosed source/evidence/policy/model/human history. Grants bind unit hash, latest human-decision sequence, authenticated recipient, purpose, redaction mode and maximum 15-minute expiry. Each download rechecks current membership/resource permissions, expiry, revocation and current revision. Redacted export materializes an allowlisted projection: remove reviewer identity and free-text rationale/internal annotations; retain action, original policy result, record/version/hash references and explicit redaction entries. It must not leak removed text through excerpts, nested payloads or metadata. Full export requires the stronger role. Export payload has its own canonical hash; original artifact hashes are provenance, not claims that removed bytes can be reconstructed. Include verification instructions and limitations. Export receipt is immutable and atomic; a download neither publishes nor grants source access. Revisions invalidate future old-version downloads; previously downloaded copies cannot be recalled.

## Application boundary and verification

Server actions/route handlers authenticate, strictly parse commands and return allowlisted actionable errors. Source retrieval rechecks current role and resource, never accepts arbitrary paths/URLs. No raw sensitive payloads in logs, analytics, task receipts or URL parameters. Origin checks for mutation/download-grant commands. All API responses private/no-store; generic denied responses reveal no evidence.

Verification requires: real disposable PostgreSQL migrations and restricted-role checks; positive, negative, missing, exclusion, conflict/date, malformed mock probabilities, timeout, cross-tenant and same-tenant foreign-procurement rejection; immutable records; changed-source revision; stale and concurrent decisions; role removal/no session; source denial; idempotency and changed-key replay; expiry/revocation/wrong recipient; redaction leakage and hash verification; transaction rollback and retry; reconstructible full and redacted exports. Synthetic-only retention: reset destroys the disposable local DB; production sensitive-data retention/deletion/backup restore remains outside enabled scope, so no private intake or production readiness claim.

Browser verification covers source disclosure, missing-evidence revision, assessment, decision/override rationale, visible success/stale error with preserved draft, export download, history and 320/375px mobile/keyboard operation. User comprehension testing with a person remains a separate unperformed acceptance item unless actually conducted. Independent technical review precedes code and an independent final review binds the delivered change. Deliver a draft PR, local run instructions, concrete checks and explicit remaining limits.
